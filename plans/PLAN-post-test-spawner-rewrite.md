# Plan: Migrate spawner.ts to package-sets + tmp-overlay

## Context

The scripts (`mk-mathlib-package.sh`, `mk-mathlib-workspace.sh`,
`test-mathlib-workspace.sh`) have proven the new approach: shared
packages in `package-sets/`, project boilerplate in `templates/`,
per-package `--tmp-overlay` mounts in bwrap. The spawner still uses
the old `installations/mathlib` layout with a single `--ro-bind` for
the whole `.lake/packages/` directory. We need to bring the spawner
in line with what the test scripts already do.

**Key architectural change:** Templates should be entirely data-driven.
The spawner discovers available templates by scanning `/data/templates/`
at runtime, not from a hardcoded list. The client fetches available
templates from a new API endpoint.

## Changes

### 1. Template format — standardize `metadata.json`

Every template directory under `/data/templates/` must have a
`metadata.json`. The `hello` template currently lacks one (it's baked
into the Docker image at `/home/templates/hello/`).

**Format:**
```json
{
  "name": "Hello World",
  "description": "Minimal Lean project",
  "packageSet": null
}
```

For mathlib (already generated by `mk-mathlib-package.sh`):
```json
{
  "name": "Lean v4.28.0 + Mathlib",
  "description": "Pre-built Mathlib dependency",
  "packageSet": "mathlib-v4.28.0"
}
```

`packageSet` is `null` (or absent) for templates with no shared
packages. When present, it names a directory under
`/data/package-sets/`.

A `blank` template needs no directory — it's just "no template".

### 2. `scripts/seed-volume.sh` (new)

A single script that handles all necessary seeding of the data
volume. Run once by an admin before first `docker run`, or re-run
to update. Idempotent.

Steps:
1. Install elan into `$ROOT/elan/` if not present (currently done
   inside `mk-mathlib-package.sh`; factor it out or call it).
2. Run `mk-mathlib-package.sh` to populate `$ROOT/package-sets/`
   and `$ROOT/templates/` with the mathlib package set and template.
3. Seed the `hello` template: copy from the repo's `templates/hello/`
   into `$ROOT/templates/hello/`, adding a `metadata.json` with
   `{ "name": "Hello World", "description": "Minimal Lean project" }`.
4. Create `$ROOT/workspaces/`, `$ROOT/db/` directories.

Args: `--root DIR` (default `$LEAN_WORKBENCH_ROOT` or `/tmp/lean-workbench`),
`--help`.

This replaces the need for admins to run multiple scripts in sequence.
The README can say: "run `./scripts/seed-volume.sh`, then `make build`,
then `make serve`."

### 3. `db.ts` — add `project_package_sets` junction table

```sql
CREATE TABLE IF NOT EXISTS project_package_sets (
  project_id  TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  package_set TEXT NOT NULL,
  PRIMARY KEY (project_id, package_set)
);
```

Each row says "project X uses package set Y". Most projects have
zero or one row; the schema supports multiple for future use.

Add helper functions:
- `getPackageSets(projectId: string): string[]`
- `addPackageSet(projectId: string, packageSet: string): void`

### 4. `db.ts` — remove hardcoded `VALID_TEMPLATES`

Remove:
```typescript
export const VALID_TEMPLATES = ['blank', 'hello', 'mathlib'] as const;
export type Template = typeof VALID_TEMPLATES[number];
```

Template validation now happens by checking if the directory exists
under `/data/templates/` (or is `'blank'`).

### 5. `spawner.ts` — constants

**Remove:**
```typescript
const MATHLIB_INSTALL_DIR = ...;
const MATHLIB_LAKE_DIR = ...;
const TEMPLATES_DIR = "/home/templates";
```

**Add:**
```typescript
const PACKAGE_SETS_DIR = `${DATA_DIR}/package-sets`;
const VOLUME_TEMPLATES_DIR = `${DATA_DIR}/templates`;
```

### 6. `spawner.ts` — new `GET /api/templates` endpoint

Returns the list of available templates by scanning
`/data/templates/`. Each entry has `id` (directory name), `name`,
and `description` from `metadata.json`. Also always includes
a synthetic `blank` entry.

```json
[
  { "id": "blank", "name": "Blank", "description": "Empty workspace" },
  { "id": "hello", "name": "Hello World", "description": "Minimal Lean project" },
  { "id": "mathlib-v4.28.0", "name": "Lean v4.28.0 + Mathlib", "description": "Pre-built Mathlib dependency" }
]
```

### 7. `spawner.ts` — rewrite `seedTemplate()`

Make it generic — no special cases per template name:

- `'blank'`: no-op, return `null`.
- Any other template: look up in `/data/templates/<template>/`.
  Read `metadata.json`. Copy all project files (`lean-toolchain`,
  `lakefile.toml`, `Main.lean`, and `lake-manifest.json` if present)
  into the workspace. Create `.lake/packages/` if `packageSet` is
  set. Return the `packageSet` value (or `null`).

### 8. `spawner.ts` — rewrite `POST /api/projects` validation

Replace the hardcoded `VALID_TEMPLATES` check and
`MATHLIB_INSTALL_DIR` existence check with:
- If template is `'blank'`, allow.
- Otherwise, check `/data/templates/<template>/metadata.json` exists.
- If the template has a `packageSet`, check that
  `/data/package-sets/<packageSet>/packages.txt` exists.

After creating the project and seeding the template, call
`addPackageSet()` if there's a package set.

### 9. `spawner.ts` — rewrite bwrap overlay args in `spawnProject()`

**Remove** the `mathlibBindArgs` block.

**Replace with:**
1. Call `getPackageSets(projectId)`.
2. For each package set, read `packages.txt` from
   `/data/package-sets/<set>/`.
3. For each package name, pre-create `.lake/packages/<pkg>/` in
   the workspace and add `--overlay-src` + `--tmp-overlay` args.
4. Add git safe.directory env vars to bwrap (with a FIXME comment
   matching the one in `test-mathlib-workspace.sh` about
   CVE-2022-24765 and the need to consider this more carefully):
   ```
   --setenv GIT_CONFIG_COUNT 1
   --setenv GIT_CONFIG_KEY_0 safe.directory
   --setenv GIT_CONFIG_VALUE_0 *
   ```

### 10. Client — fetch templates from API

**`client/src/api.ts`**: Add `fetchTemplates()` calling
`GET /api/templates`.

**`client/src/ProfilePage.tsx`**: Replace the hardcoded template
list (lines 198-201) with a `useEffect` that calls `fetchTemplates()`
and populates the selector dynamically. The `blank` entry is always
available as a fallback.

### 11. `plans/LEAN-TOOLS.md` — update naming

Change `packages/` to `package-sets/` throughout.

- `Dockerfile` — already has bwrap 0.11.0
- `templates/hello/` in repo — still baked into image, copied to
